# Onboard Memory Manager (Web)

마우스에 저장된 설정을 브라우저에서 읽고 수정하는 정적 웹앱입니다. Logitech G 마우스의 온보드 메모리 프로필과 VGN 마우스의 설정을 다룹니다.
WebHID로 기기와 직접 통신하며(Logitech은 HID++ 2.0의 기능 `0x8100`, VGN은 16바이트 설정 프로토콜), 빌드나 서버 측 코드가 없습니다.

## 실행

WebHID를 지원하는 데스크톱 Chrome / Edge / Opera가 필요합니다.

설치 없이 <https://sunya0804.github.io/logitech_omm/> 에서 바로 쓸 수 있습니다. 직접 띄우려면 이 폴더에서:

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

그다음 <http://127.0.0.1:8765> 을 엽니다.

G HUB나 공식 OMM이 실행 중이면 HID++ 통신이 충돌할 수 있으니 먼저 종료하세요.

## 기능

- 프로필 읽기, 사용/사용 안 함 전환, 활성 프로필 전환, 온보드/호스트 모드 전환
- 프로필 이름, 보고율, DPI 단계(최대 5개)·기본 단계·시프트 단계 편집
- 리프트오프 거리(형식 7), 버니합 방지 시간(형식 7~8) 편집
- HITS 구성(좌·우 버튼의 작동점, 래피드 트리거, 클릭 햅틱) 편집 — 형식 8. 저장하면 현재 값에도 바로 적용
- 버튼 할당(기본 / G-Shift): 마우스 버튼, 키보드 단축키, 미디어 키, 특수 기능, 사용 안 함
- 프로필 백업 내보내기 / 불러오기 (JSON)
- 마우스 테스트: 더블클릭(채터링)·버튼·휠 역방향 튐 검사, 보고율 측정. 기기 연결 없이 어떤 마우스에서도 동작
- 진단 정보 내보내기: 기능 목록과 온보드 메모리 전체를 읽기 전용으로 덤프 (새 기기 지원용)

조명(LED)과 매크로 편집은 지원하지 않으며, 기존 값은 그대로 보존됩니다.

## VGN 마우스

제조사 ID `0x3554`를 쓰는 VGN 계열의 16바이트 설정 프로토콜을 지원합니다. 보고율, 리프트오프 거리, DPI 단계(50~42,000),
모션 싱크·각도 스냅·리플 컨트롤, 디바운스, 버튼 재할당, 자동 절전을 편집합니다.

- 실기기 확인: VGN DragonFly F2 Ultra+ (무선 수신기 연결, 읽기와 저장)
- 연결할 때 읽은 값이 알려진 구조와 맞지 않으면 지원하지 않는 기기로 처리하고 아무것도 쓰지 않습니다.
- 저장할 때는 바뀐 바이트만 기록하고 다시 읽어 대조합니다. 왼쪽 클릭이 어느 버튼에도 없으면 저장을 막습니다.
- DPI 단계 수는 연결 당시의 개수보다 늘리지 않습니다.
- 명령 번호와 저장 위치는 [OpenMouse](https://github.com/OpenMouse-Project/mouse-protocol)가 정리한 내용을 참고했습니다(코드는 가져오지 않음).

## 프로필 형식

| 형식 | 구조 | 실기기 확인 | 비고 |
| --- | --- | --- | --- |
| 1~5 | 기본 (`classic`) | PRO X Wireless (4), G502 X PLUS (5) | |
| 6 | 확장 (`extendedBasic`) | 없음 | 보고율이 무선/유선 따로(최대 8000 Hz), DPI 단계가 X/Y/리프트오프 거리 |
| 7 | 확장 (`extended`) | PRO X 2 DEX | 형식 6 + 버니합 방지 시간 |
| 8 | 확장 + HITS (`analog`) | 직접 확인 못 함 | PRO X2 / X3 SUPERSTRIKE. 버튼별 작동점·래피드 트리거·클릭 햅틱. 공개된 실기기 덤프와 구조 일치 |
| 10 | 기본 + 세로 DPI (`classicDpiY`) | 없음 | 펌웨어 업데이트 이후의 G502 X 계열. 보고율은 편집하지 않음 |
| 그 외 | 데이터로 자동 판별 | 없음 | |

형식별 필드 위치는 공식 Onboard Memory Manager 2.7과 대조했고, 형식 8과 리프트오프 거리·버니합 값의 의미는 [OpenMouse](https://github.com/OpenMouse-Project/mouse-protocol)가 공개한 실기기 관찰 기록과도 맞춰 보았습니다(코드는 가져오지 않음). 형식 6과 10은 경고에 동의해야 편집할 수 있습니다.
HITS 값의 허용 범위는 기기가 알려 주는 단계 수(HID++ `0x1B0C`)를 따르며, 읽지 못하면 기본 범위(작동점 1~10, 래피드 트리거 1~5, 햅틱 0~5)를 씁니다.

## 안전장치

- 편집은 메모리 상에서만 이뤄지고 「기기에 저장」을 눌러야 기록됩니다.
- 기기에서 CRC가 맞는 섹터를 하나라도 읽어야 쓰기가 허용됩니다.
- 섹터를 쓴 뒤 다시 읽어 내용을 대조합니다.
- 실기기 데이터로 확인된 프로필 형식(1~5, 7, 8) 외에는 사용자가 명시적으로 허용해야 편집할 수 있고, 데이터가 알려진 구조로 읽히지 않으면 편집이 막힙니다.
- 알지 못하는 필드는 건드리지 않고 원본 바이트를 그대로 다시 씁니다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `js/compx.js` | VGN 계열 16바이트 설정 프로토콜과 설정 이미지 해석/수정 |
| `js/compx-ui.js` | VGN 계열 기기의 설정 화면 |
| `js/mock-compx.js` | 개발·테스트용 가상 VGN 기기 (페이지에서는 불러오지 않음) |
| `js/hidpp.js` | WebHID 전송 계층, HID++ 2.0 요청/응답, 온보드 프로필 명령 |
| `js/profile.js` | 프로필 섹터 바이너리 해석/수정, CRC, 프로필 디렉터리 |
| `js/keys.js` | 키·버튼·특수 기능 이름표 |
| `js/tester.js` | 마우스 테스트 화면과 판정 로직 |
| `js/mock.js` | 개발·테스트용 가상 HID++ 기기 (페이지에서는 불러오지 않음) |
| `js/app.js` | 화면과 상태 관리 |

프로토콜과 프로필 레이아웃은 [libratbag](https://github.com/libratbag/libratbag)의 `hidpp20.c`를 참고했습니다.

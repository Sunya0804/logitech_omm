# GOMM — Global Onboard Memory Manager

마우스에 저장된 설정을 브라우저에서 읽고 수정하는 정적 웹앱입니다. Logitech G, VGN·ATK 및 MCHOSE 지원 기종의 설정을 다룹니다.
WebHID로 기기와 직접 통신하며(Logitech은 HID++ 2.0의 기능 `0x8100`, VGN은 16바이트 설정 프로토콜), 빌드나 서버 측 코드가 없습니다.

## 실행

WebHID를 지원하는 데스크톱 Chrome / Edge / Opera가 필요합니다.

설치 없이 <https://sunya0804.github.io/logitech_omm/> 에서 바로 쓸 수 있습니다. 직접 띄우려면 이 폴더에서:

```powershell
python -m http.server 8765 --bind 127.0.0.1   # 또는 npm run serve
```

그다음 <http://127.0.0.1:8765> 을 엽니다.

G HUB나 공식 OMM이 실행 중이면 HID++ 통신이 충돌할 수 있으니 먼저 종료하세요.

## 기능

- 프로필 읽기, 사용/사용 안 함 전환, 활성 프로필 전환, 온보드/호스트 모드 전환
- 프로필 이름, 보고율, DPI 단계(최대 5개)·기본 단계·시프트 단계 편집
- 리프트오프 거리(형식 7), 버니합 방지 시간(형식 7~8) 편집
- HITS 구성(좌·우 버튼의 작동점, 래피드 트리거, 클릭 햅틱) 편집 — 형식 8. 저장하면 현재 값에도 바로 적용
- 버튼 할당(기본 / G-Shift): 마우스 버튼, 키보드 단축키, 미디어 키, 특수 기능, 사용 안 함, 매크로
- 매크로(매크로 형식 1): 기존 매크로의 키·대기·마우스 버튼 단계 표시, 키보드 녹화·대기·마우스 클릭 추가로 편집. **매크로 기록은 실기기로 아직 확인하지 않았습니다** (아래 「매크로」)
- 프로필 백업 내보내기 / 불러오기 (JSON). VGN·ATK·MCHOSE는 지금 프로필의 편집 가능한 설정을 같은 기종끼리 주고받음
- 마우스 테스트: 더블클릭(채터링)·버튼·휠 역방향 튐 검사, 보고율 측정, DPI·센서 기울기 실측(자를 대고 정한 거리만큼 이동). 기기 연결 없이 어떤 마우스에서도 동작
- 데모 모드: 홈의 「기기 없이 둘러보기」에서 Logitech·VGN·ATK·MCHOSE 가상 기기로 편집·저장을 시험. 가상 기기는 메모리 안에서만 동작하며 WebHID에 접근하지 않음(MCHOSE는 실기기에서 읽어 둔 응답을 재생)
- 진단 정보 내보내기: 기능 목록과 온보드 메모리 전체를 읽기 전용으로 덤프 (새 기기 지원용)
- 화면 언어: 한국어·영어 (브라우저 언어로 고르고, 왼쪽 아래 선택 상자로 바꿀 수 있음). 키보드만으로 조작할 수 있고 화면 읽기 프로그램용 이름표를 붙였습니다.

조명(LED)은 지원하지 않으며, 기존 값은 그대로 보존됩니다.

### 매크로

- 버튼 할당 `[0x00, 섹터, 0x00, 위치]`가 매크로의 시작을 가리킵니다. 명령은 대기(0x40), 마우스 버튼(0x41/0x42), 키(0x43/0x44, [수정자, 키]), 미디어 키(0x45/0x46), 점프(0x60), 끝(0xFF)이며 libratbag에 공개된 정보를 따랐습니다. OpenMouse는 할당을 `[0x00, 버튼, 섹터, 0x00]`으로 다르게 적고 있어 실기기 확인이 필요합니다.
- 반복·누르는 동안 반복·휠·포인터 이동 같은 명령이 든 매크로는 표시만 하고, 새로 녹화하면 대신합니다.
- 저장할 때는 어느 프로필도 쓰지 않고 내용이 모두 0xFF인 섹터에 새로 기록한 뒤 버튼이 그 섹터를 가리키게 합니다. 기존 매크로 섹터는 다른 버튼이 함께 쓸 수 있어 덮어쓰지 않습니다(빈 섹터가 모자라면 저장을 막습니다).
- 백업에는 매크로 단계가 함께 들어가고, 불러오면 저장 전 편집본이 됩니다.

## VGN 마우스

제조사 ID `0x3554`를 쓰는 VGN 계열의 16바이트 설정 프로토콜을 지원합니다. 보고율, 리프트오프 거리, DPI 단계(50~42,000),
모션 싱크·각도 스냅·리플 컨트롤, 디바운스, 버튼 재할당, 자동 절전을 편집합니다.

- 실기기 확인: VGN DragonFly F2 Ultra+ (무선 수신기 연결, 읽기와 저장)
- 연결할 때 읽은 값이 알려진 구조와 맞지 않으면 지원하지 않는 기기로 처리하고 아무것도 쓰지 않습니다.
- 저장할 때는 바뀐 바이트만 기록하고 다시 읽어 대조합니다. 왼쪽 클릭이 어느 버튼에도 없으면 저장을 막습니다.
- DPI 단계 수는 연결 당시의 개수보다 늘리지 않습니다.
- 프로필 전환(4개)과 DPI 표시등(켬/끔, 숨쉬기, 밝기, 단계별 색)을 지원합니다. 본체 RGB 조명은 지원하지 않습니다. 두 기능 모두 DragonFly F2 Ultra+ 실기기에서 동작을 확인했습니다.
- 명령 번호와 저장 위치는 [OpenMouse](https://github.com/OpenMouse-Project/mouse-protocol)가 정리한 내용을 참고했습니다(코드는 가져오지 않음).

## ATK 마우스

ATK(제조사 ID `0x373b`)는 VGN과 같은 프로토콜을 쓰지만 센서에 따라 DPI 저장 방식과 선택지가 다릅니다.
그래서 기종을 세 단계로 나눠 다룹니다.

- **확인된 기종**(아래 표): 바로 편집할 수 있습니다.
- **미확인 기종**(`js/compx-models.js`의 기종 중 확인된 기종을 제외): ATK HUB의 기종표로 센서와 DPI 저장 방식을 알 수 있는 기종입니다. 연결하면 값을 보여 주기만 하고, 화면의 값이 ATK HUB와 같은 것을 확인했다고 체크해야 편집이 열립니다. 리프트오프 거리는 기종마다 저장 값의 뜻이 달라 바꿀 수 없습니다.
- **그 밖의 기종**: "지원하지 않는 기종"으로 거부하고 진단 파일 저장을 제안합니다. 같은 식별값을 DPI 저장 방식이 다른 기종이 함께 쓰는 경우(무선 연결에서는 가려낼 수 없음)와, 아직 해석하지 못하는 센서(PAW3955 Master, PAW3395 SE, PAW3315, PAW3311, PAW3320)가 여기에 해당합니다.

| 기종 | 식별값 (CID, MID) | DPI | 리프트오프 | 비고 |
| --- | --- | --- | --- | --- |
| ATK X1 Pro Max | 2, 39 | 50~36,000 | 0.7 / 1 / 2 mm | |
| ATK A9 Plus Nearlink | 2, 83 | 100~30,000 | 1 / 2 mm | 보고율 최대 1,000 Hz |
| ATK F1 LEVIATAN 2.0 | 1, 13 | 10~42,000 | 0.7~1.7 mm (0.1 단위) | PAW3950 Ultra. DPI를 10 단위로 저장 |
| ATK Ghost Ultimate | 1, 24 | 10~42,000 | 0.7~1.7 mm (0.1 단위) | PAW3950 Ultra. DPI를 10 단위로 저장 |
| ATK A9 Ultra | 2, 87 | 10~42,000 | 읽기 전용 | 사용자 동작 확인으로 미검증 경고 제거 |

- X1 Pro Max와 A9 Plus Nearlink는 이 프로젝트에서 실기기로 확인한 적이 없습니다. 값은 OpenMouse가 ATK HUB와 실기기로 대조해 둔 내용을 따랐습니다.
- F1 LEVIATAN 2.0은 실기기(8K 수신기 연결)에서 읽은 DPI 단계와 리프트오프 값이 ATK HUB에 보이는 값과 맞는 것을 확인했습니다. 10,000을 넘는 DPI의 저장 방식과 리프트오프 범위는 OpenMouse의 정리를 따랐고 실기기로 확인하지 않았습니다.
- Ghost Ultimate는 실기기(8K 수신기 연결)의 설정 메모리가 F1 LEVIATAN 2.0과 같은 구조로 읽히는 것을 확인했습니다.
- A9 Ultra는 2026-10-14 사용자가 정상 동작을 확인하고 적용을 요청했습니다. 이후 ATK 8K 동글(`373b:101b`)로 설정 185바이트를 두 번 읽어 일치와 체크섬을 확인했습니다. DPI 단계 800/1,000/1,600/3,200, 현재 1,600 DPI, 1,000 Hz, 프로필 1을 확인했습니다. 해당 식별값만 미검증 경고 없이 편집하도록 반영했습니다. 실제 기기의 저장·프로필 전환을 자동 검사한 것은 아닙니다.
- 미확인 기종의 식별값·이름·센서는 OpenMouse가 ATK HUB에서 정리한 기종표에서 옮겨 적었습니다(코드는 가져오지 않음). 이 기종들은 이 프로젝트에서 실기기로 확인한 적이 없습니다.
- ATK는 현재 프로필 응답이 유효한 기종에 프로필 4개를 표시합니다. 전환 후 설정과 활성 번호를 다시 읽고 확인합니다. 미검증 기종은 편집 허용 후 전환할 수 있습니다. 조명은 제공하지 않습니다.

### ATK 매크로

버튼 탭에서 매크로를 보고 편집합니다(Logitech과 같은 편집 칸: 키보드 녹화, 대기, 마우스 클릭). **매크로 기록은 실기기로 아직 확인하지 않았습니다.**
저장 방식은 ATK V3 HUB(v3-hub.atk.store)의 동작을 보고 정리했습니다(코드는 가져오지 않음).

- 프로필마다 매크로 칸 12개(M1~M12)가 `0x0300`부터 384바이트 간격으로 있습니다. 칸은 HUB가 늘 같은 값으로 쓰는 31바이트 머리, 이벤트 수(1~70), 5바이트 이벤트 `[상태, 값 1, 값 2, 대기(ms, 2바이트)]`, 검사 바이트로 이뤄집니다.
- 버튼 기록은 `[6, 칸 번호, 반복 방식]`입니다. 반복 방식은 정한 횟수(1~252), 다시 누를 때까지(253), 누르는 동안(254), 아무 키나 누를 때까지(255) 중에서 고릅니다.
- 이 버튼만 쓰는 칸이면 그 칸을 고쳐 쓰고, 아니면 비어 있고 어느 버튼도 쓰지 않는 칸에 기록합니다. HUB의 매크로 목록에 남아 있는 매크로는 버튼에 걸려 있지 않아도 덮어쓰지 않습니다.
- 매크로를 먼저 기록하고 다시 읽어 대조한 뒤 버튼 기록을 씁니다.
- 휠·미디어 키처럼 화면에서 다루지 않는 이벤트는 원래 바이트대로 보여 주고 그대로 다시 기록합니다.
- 백업에는 버튼에 걸린 매크로가 함께 들어가고, 불러오면 같은 칸 번호로 되돌리는 저장 전 편집본이 됩니다.
- VGN은 같은 프로토콜을 쓰지만 매크로 저장 방식을 확인하지 못해 매크로를 열지 않습니다.

## MCHOSE 마우스

M HUB(제조사 웹 드라이버)가 쓰는 세 가지 통신 방식(A5 1세대·V2·V3)을 이 프로젝트에서 직접 구현했습니다(js/mchose.js).
명령 번호와 바이트 위치는 M HUB의 동작과 [OpenMouse](https://github.com/OpenMouse-Project/mouse-protocol)가 공개한 관찰 기록을 사실 정보로 참고했습니다(코드는 가져오지 않음).
**40개 기종·연결 변형 항목**을 등록했습니다. 회사의 모든 과거·미래 제품이 검증됐다는 의미는 아닙니다.
기종표와 검증 범위는 [MCHOSE 지원 문서](docs/mchose-support.md)를 참고하세요.

- DPI 단계 값·활성 단계, 보고율, 리프트오프 거리(V2·A5), 디바운스, 절전, 모션 싱크·각도 스냅·리플 컨트롤, 성능 모드, 센서 각도, 버튼 할당을 기종별로 제공합니다.
- 기존 프로필 전환은 확인 후 즉시 적용합니다. 그 외 편집은 「기기에 저장」 전까지 기기에 쓰지 않습니다.
- 연결할 때는 읽기만 합니다. 표시값을 M HUB와 대조한 뒤 편집을 허용하는 체크박스를 켭니다.
- 저장 전 외부 변경 여부를 확인하고 저장 후 값을 다시 읽어 검증합니다. 실패하면 추가 쓰기를 막고 다시 읽기를 요구합니다.
- 왼쪽 버튼 재할당, 매크로 작성, 조명·MagDock 제어, 펌웨어 업데이트는 제공하지 않습니다.
- 설정 백업은 같은 기종·세대끼리만 불러옵니다. 이 기기의 선택지·범위에 맞지 않는 값, DPI 단계 수가 다른 DPI 값, 왼쪽 버튼 값은 옮기지 않고 알려 줍니다.
- K7 Ultra(3837:1001 → 본체 4150)와 A7 V2 Ultra+(3837:100B → 본체 4021)는 이 PC에서 설정 읽기를 확인했습니다. **실기기 저장은 수행하지 않았습니다.**
- 지원하지 않는 구조·미확인 기종은 읽기 전용으로 두고 진단 파일을 내보낼 수 있습니다. 세대가 다른 프로토콜을 무작정 시도하지 않습니다.

실행 중 외부 서버에서 드라이버를 가져오지 않습니다.

개발 검증 방법은 아래 「개발」 절을 참고하세요.

`js/mock-mchose.json`은 두 실기기의 읽기 전용 응답입니다.
테스트의 쓰기 명령은 가상 기기의 메모리에서만 실행됩니다.

## VIA 키보드

VIA(QMK) 키보드의 키맵·레이아웃 옵션·매크로·조명/설정 메뉴를 다루고, 키 테스트(스위치 매트릭스)를 보여 줍니다.
화면 작업 지시는 [docs/codex-via-frontend.md](docs/codex-via-frontend.md)에 있습니다.

- 키보드마다 VIA 정의 파일(JSON)이 필요합니다. usevia.app 목록에 있는 키보드는 자동으로 받고, 없는 키보드는 제작사 웹 허브의 링크로 받은 파일을 불러옵니다.
  - 예: Qwertykeys QK80 MK2 → `https://cfg.qwertykeys.com/definitions/v3/1363889410.json`
  - QK80 MK2는 제작사 정의 파일을 사이트에 함께 실어 두어 바로 열립니다([definitions/README.md](definitions/README.md), 이 저장소의 라이선스 대상 아님). 사용자가 직접 불러온 파일이 있으면 그쪽을 먼저 씁니다.
- 키 코드는 VIA 프로토콜 12(QMK 0.19 이후 체계)만 편집합니다. 그보다 오래된 키보드는 읽기만 합니다.
- VIA 앱의 「Save + Load」 레이아웃 파일(.layout.json)을 불러오고 내보낼 수 있습니다(키맵·인코더·매크로). 불러온 내용은 저장을 눌러야 기록됩니다.
- 공장 초기화·부트로더 진입·키맵 초기화 명령은 보내지 않습니다. 초기화 같은 메뉴 동작은 값으로 읽지도 않습니다.
- 실기기(QK80 MK2)에서 읽기 명령의 응답(`tests/fixtures/via-qk80mk2.json`, 정의 파일은 넣지 않음), 키 테스트, 키맵 저장을 확인했습니다. 매크로·인코더·설정 메뉴 저장과 VIA 레이아웃 파일 불러오기는 가상 기기로만 시험했습니다.
- 매크로는 단계 목록과 VIA 식(`Hello{KC_ENT}{100}`) 두 가지로 편집할 수 있습니다.

### Vial

[Vial](https://get.vial.today/) 펌웨어 키보드도 같은 화면에서 다룹니다. 통신 방식은 vial-qmk·vial-gui의 공개 소스로 확인했고 코드는 가져오지 않았습니다.

- 정의 파일은 키보드 펌웨어에 xz로 압축돼 들어 있어 따로 받을 필요가 없습니다. 압축은 `js/xz.js`가 풉니다(Python으로 만든 표본으로 시험).
- Vial 프로토콜 6(QMK 0.19 이후 키 코드)부터 키맵을 편집합니다. 그 전 펌웨어는 키맵을 읽기만 합니다.
- 탭 댄스·콤보·키 오버라이드(켜기, 수정자, 누른 키 → 바꿀 키)와 QMK 설정(탭 판정 시간, 자동 Shift, 키 바꾸기 등)을 편집합니다. 기록한 뒤 다시 읽어 대조합니다.
- 잠겨 있는 키보드는 매크로 기록·QK_BOOT 지정·키 시험을 받지 않으므로, 「잠금 풀기」에서 키보드가 정한 키를 누르고 있으면 풀립니다. 잠금(lock)·QMK 설정 초기화·부트로더 명령은 보내지 않습니다.
- Vial 키보드는 VIA 프로토콜을 9로 알리기 때문에, 프로토콜 9인 키보드에만 Vial 확인 명령을 보냅니다.
- 실기기로는 확인하지 못했습니다. 가상 Vial 키보드(`js/mock-via.js`, 데모의 「Vial 키보드」)로 시험했습니다.

## 홈 제품 사진

사진을 확인한 기종은 연결 후 홈 카드에 배경이 투명한 제품 사진을 표시합니다.
등록 기종과 기본 그림으로 대체하는 조건은 [제품 사진 문서](docs/device-images.md)를 참고하세요.

## 프로필 형식

| 형식 | 구조 | 실기기 확인 | 비고 |
| --- | --- | --- | --- |
| 1~5 | 기본 (`classic`) | PRO X Wireless (4), G502 X PLUS (5) | |
| 6 | 확장 (`extendedBasic`) | 없음 | 보고율이 무선/유선 따로(최대 8000 Hz), DPI 단계가 X/Y/리프트오프 거리 |
| 7 | 확장 (`extended`) | PRO X 2 DEX | 형식 6 + 버니합 방지 시간 |
| 8 | 확장 + HITS (`analog`) | 직접 확인 못 함 | PRO X2 / X3 SUPERSTRIKE. 버튼별 작동점·래피드 트리거·클릭 햅틱. 공개된 실기기 덤프와 구조 일치 |
| 10 | 기본 + 세로 DPI (`classicDpiY`) | 없음 | 펌웨어 업데이트 이후의 G502 X 계열. 보고율은 편집하지 않음 |
| 그 외 | 데이터로 자동 판별 | 없음 | |

형식별 필드 위치는 공식 Onboard Memory Manager 2.7과 대조했고, 형식 8과 리프트오프 거리·버니합 값의 의미는 [OpenMouse](https://github.com/OpenMouse-Project/mouse-protocol)가 공개한 실기기 관찰 기록과도 맞춰 보았습니다(코드는 가져오지 않음). 형식 6과 10은 경고에 동의해야 편집할 수 있습니다.
HITS 값의 허용 범위는 기기가 알려 주는 단계 수(HID++ `0x1B0C`)를 따르며, 읽지 못하면 기본 범위(작동점 1~10, 래피드 트리거 1~5, 햅틱 0~5)를 씁니다.

## 안전장치

- 편집은 메모리 상에서만 이뤄지고 「기기에 저장」을 눌러야 기록됩니다.
- 기기에서 CRC가 맞는 섹터를 하나라도 읽어야 쓰기가 허용됩니다.
- 섹터를 쓴 뒤 다시 읽어 내용을 대조합니다.
- 실기기 데이터로 확인된 프로필 형식(1~5, 7, 8) 외에는 사용자가 명시적으로 허용해야 편집할 수 있고, 데이터가 알려진 구조로 읽히지 않으면 편집이 막힙니다.
- 알지 못하는 필드는 건드리지 않고 원본 바이트를 그대로 다시 씁니다.
- Logitech 매크로는 빈 섹터에만 기록하고, 기존 매크로 섹터는 덮어쓰지 않습니다. ATK 매크로는 그 버튼만 쓰는 칸이나 빈 칸에만 기록합니다.

## 구조

빌드 단계 없이 브라우저가 바로 읽는 ES 모듈입니다. `index.html`은 `js/app.js` 하나만 불러옵니다.

| 파일 | 역할 |
| --- | --- |
| `js/app.js` | 앱 뼈대: 기기 선택과 브랜드별 화면 연결, 홈·상태 줄·저장 막대, 데모, 언어 전환 |
| `js/ui.js` | 화면 공통 도우미(DOM 생성, 알림, 확인 창, 탭, 작업 중 표시)와 앱 상태 |

| `js/logitech-ui.js` | Logitech 온보드 프로필 설정 화면 |

| `js/profile.js` | 프로필 섹터 바이너리 해석/수정, CRC, 프로필 디렉터리 |
| `js/macro.js` | Logitech 온보드 매크로 해석/기록, 키보드 녹화 변환 |

| `js/keys.js` | 키·버튼·특수 기능 이름표 |

| `js/compx-ui.js` | VGN·ATK 기기의 설정 화면 |
| `js/compx-macro.js` | ATK 온보드 매크로 칸 해석/기록 |
| `js/mchose.js`, `js/mchose-models.js`, `js/mchose-actions.js` | MCHOSE 드라이버, 기종표, 버튼 동작 표 |

| `js/tester.js` | 마우스 테스트 화면과 판정 로직 |
| `js/device-images.js` | 홈 카드 제품 사진 목록 |

## 개발

Node 22 이상이 필요합니다. 브라우저 테스트는 설치된 Chrome을 씁니다.

```powershell
npm install
npm test                 # 단위 테스트 + 가상 기기 브라우저 테스트
npm run test:unit        # 단위 테스트만 (프로필 해석, MCHOSE 드라이버, 번역표)
npm run serve            # http://127.0.0.1:8765
```

- Chrome 경로가 기본 위치가 아니면 `CHROME_PATH`를 지정하세요. `SCREENSHOT_DIR`을 주면 브라우저 테스트가 화면을 저장합니다.
- 화면 문구는 코드에 한국어로 쓰고 `t('문구')`로 감쌉니다. 새 문구는 `js/i18n-en.js`에 영어를 추가해야 하며, 빠지면 `tests/i18n.test.mjs`가 실패합니다.
- GitHub Actions(`.github/workflows/test.yml`)가 푸시마다 `npm test`를 돌립니다.
